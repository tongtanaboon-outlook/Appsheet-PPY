# 09 — ออกแบบ: ตรวจตำแหน่งจุดส่งสินค้าปลายทาง เทียบกับ `LatLong_Actual`

> **เป้าหมาย**: เมื่อ `ตารางงานประจำวัน.LatLong_Actual` มีข้อมูล
> ให้ `SCGนครหลวงJWDภูมิภาค` ตรวจสอบ `จุดส่งสินค้าปลายทาง` ของทั้ง 2 ชีต/2 คอลัมน์
> — ถ้าห่างเกิน **20 เมตร** จะ **บันทึกไม่ได้** แต่มีปุ่มให้กดยืนยันว่าตำแหน่งปัจจุบันถูกต้อง
> และต้องมีข้อความบอกว่า **"มีแก้ไข โดยคนนี้"**

## 1. ⚠️ 3 เรื่องที่ต้องเช็คก่อนลงมือ

### 1.1 `SM_Link_SCG` อาจชี้ผิดแถว (ข้อเสี่ยงสูงสุด)

```
SM_Link_SCG = ANY(SELECT(ตารางงานประจำวัน[ID_งานประจำวัน],
   AND([Invoice No] = ANY([_THISROW].[Invoice No]),
       [_ROWNUMBER] = MIN(SELECT(ตารางงานประจำวัน[_ROWNUMBER], ...)))))
```
→ **เลือกแถวแรกสุดของ invoice เสมอ** แต่ `ตารางงานประจำวัน` มีหลายจุดส่งต่อ 1 shipment
(มีคอลัมน์ `จำนวนปลายทาง_System`, `ลำดับแรก`, `จำนวนจุดที่ส่งจริง` ยืนยันเรื่องนี้)
→ ถ้า 1 shipment มี 3 จุดส่ง ระยะทางที่วัดจะเทียบกับจุดผิด → **ผลตรวจผิดทั้งระบบ**

**วิธีแก้ (แนะนำ):** ใช้ `MATCH_KEY` ที่มีอยู่ทั้ง 2 ชีต ดึงด้วย LOOKUP 4 อาร์กิวเมนต์
(ไม่ต้องสร้าง Ref ใหม่ และไม่เกิด circular reference)
```
=IF(ISBLANK([MATCH_KEY]), "",
    LOOKUP([_THISROW].[MATCH_KEY], "ตารางงานประจำวัน", "MATCH_KEY", "LatLong_Actual"))
```
> **ต้องยืนยันก่อนว่า `MATCH_KEY` 1 ค่า = 1 จุดส่งจริง** (เปิดตารางงานประจำวันดูว่า MATCH_KEY ซ้ำกันไหม)
> ถ้าซ้ำ → ใช้ Invoice No + ชื่อปลายทาง + ลำดับแถวแทน
> หมายเหตุ: `ชื่อปลายทาง` ในชีต SCG ดึงมาจาก `SM_Link_SCG` อยู่แล้ว → การใช้มันเป็นเงื่อนไขจะเป็น circular

### 1.2 `Valid_If` ไม่ได้บล็อกทุกกรณี

จากเอกสาร AppSheet:
> *"For data changes made through forms or Quick Edit columns in detail views, `Valid_If` constraints are only enforced for **visible inputs**."*
> *"For updates made through actions, `Valid_If` conditions are enforced in two cases: (1) If the column being updated becomes invalid… (2) If the update causes a different column to become invalid… This means **an action won't be blocked due to preexisting invalid values** that are unrelated to the action itself."*

→ **สองข้อสรุปที่ออกแบบได้:**
1. ต้องวางเงื่อนไขไว้บนคอลัมน์ที่ **มองเห็นได้ในฟอร์ม** ไม่งั้นไม่บล็อก
   (`จุดส่งสินค้าปลายทาง` เป็น `Visible? = ALWAYS` ✅)
2. **ปุ่ม Action ที่เซ็ตคอลัมน์อื่น จะไม่ถูกบล็อก** จากค่าที่ผิดเงื่อนไขที่มีอยู่ก่อนแล้ว
   → นี่คือกลไกที่ทำให้ "ปุ่มยืนยัน" ทำงานได้จริง ✅

### 1.3 ต้องบล็อก "กดบันทึก" ไม่ใช่แค่บล็อกช่องพิกัด

`Valid_If` บน `จุดส่งสินค้าปลายทาง` จะบล็อกเมื่อผู้ใช้ **แก้** คอลัมน์นั้น
แต่ถ้าผู้ใช้ไม่แตะ (ค่ามาจาก `=HERE()` อยู่แล้ว) → อาจไม่ trigger
→ ต้องมี **`Required_If` บนคอลัมน์ช่วย** เป็นชั้นที่ 2 (ดู §3)

## 2. คอลัมน์ที่ต้องเพิ่ม — 5 ตัว (ในชีต `SCGนครหลวงJWDภูมิภาค`)

| # | ชื่อคอลัมน์ | ชนิด | สูตร / ค่า | หน้าที่ |
|---:|---|---|---|---|
| 1 | `LatLong_จากงานประจำวัน` | LatLong | `=IF(ISBLANK([MATCH_KEY]), "", LOOKUP([_THISROW].[MATCH_KEY], "ตารางงานประจำวัน", "MATCH_KEY", "LatLong_Actual"))` | ดึงจุดอ้างอิงจากชีตงานประจำวัน (เก็บเป็นค่า LatLong เต็ม) |
| 2 | `ระยะจากLatLong_Actual_เมตร` | Decimal | `=IF(OR(ISBLANK([LatLong_จากงานประจำวัน]), ISBLANK([จุดส่งสินค้าปลายทาง])), "", DISTANCE([จุดส่งสินค้าปลายทาง], [LatLong_จากงานประจำวัน]) * 1000)` | ระยะทางเป็น **เมตร** |
| 3 | `ยืนยันตำแหน่ง` | Yes/No | *ค่าว่าง* (เซ็ตโดย Action หรือติ็กเอง) | flag ว่า "ผู้ใช้ยืนยันแล้ว" — ใช้ปลดล็อกการบันทึก |
| 4 | `ผู้ยืนยันตำแหน่ง` | Text | `=IF(ISBLANK([ยืนยันตำแหน่ง]), "", USEREMAIL())` | ใครเป็นคนยืนยัน |
| 5 | `ข้อความแก้ไขตำแหน่ง` | LongText | ดู §5 | ข้อความ "มีแก้ไข โดยคนนี้ เมื่อ …" |

> **ทางเลือก (ถ้า `LOOKUP` คืนค่า LatLong ไม่ได้):** แยกเก็บเป็น 2 คอลัมน์ Decimal
> `LAT_งาน` = `=IF(ISBLANK([MATCH_KEY]), "", LAT(LOOKUP([_THISROW].[MATCH_KEY], "ตารางงานประจำวัน", "MATCH_KEY", "LatLong_Actual")))`
> `LONG_งาน` = เหมือนกันแต่ใช้ `LONG()`
> แล้วใช้ `DISTANCE([จุดส่งสินค้าปลายทาง], LATLONG([LAT_งาน],[LONG_งาน])) * 1000`
> (แน่นอนกว่าเรื่องชนิดข้อมูล 100%)

## 3. กลไกบล็อกการบันทึก — 2 ชั้น

### ชั้นที่ 1 — `Valid_If` บน `จุดส่งสินค้าปลายทาง` (ข้อความสวย)

```
Valid_If:
=OR(
  ISBLANK([LatLong_จากงานประจำวัน]),                                    -- ไม่มีจุดอ้างอิง = ไม่ตรวจ
  [ระยะจากLatLong_Actual_เมตร] <= 20,                                    -- ใกล้พอ = ผ่าน
  ISBLANK([ยืนยันตำแหน่ง]) == FALSE                                       -- ยืนยันแล้ว = ปล่อยให้บันทึก
)

Error_Message_If_Invalid:
="จุดส่งสินค้าปลายทางที่คุณกรอกห่างจากตำแหน่งจริงที่ระบบบันทึกไว้ "
& TEXT([ระยะจากLatLong_Actual_เมตร], "0.0")
& " ม. (เกิน 20 ม.) — ถ้าตำแหน่งนี้ถูกต้อง ให้กดปุ่ม 'ยืนยันตำแหน่ง' ด้านล่าง"
```

### ชั้นที่ 2 — `Required_If` บน `ยืนยันตำแหน่ง` (บล็อก "กดบันทึก" จริง)

```
Required_If:
=AND(
  NOT(ISBLANK([LatLong_จากงานประจำวัน])),
  [ระยะจากLatLong_Actual_เมตร] > 20
)
```
→ ระหว่างที่ห่างเกิน 20 ม. **ช่องนี้จะกลายเป็น "required"** → AppSheet ไม่ให้กด Save
→ ผู้ใช้ติ็ก (หรือกดปุ่ม Action ที่เซ็ตค่าให้) → ช่องไม่ว่าง → บันทึกได้ ✅

> ทำไมต้องมี 2 ชั้น: `Valid_If` ให้ **ข้อความที่เข้าใจง่าย** ส่วน `Required_If` เป็นตาข่ายนิรภัย
> กันกรณีผู้ใช้ไม่ได้แตะช่องพิกัดเลย (ค่ามาจาก `=HERE()`)

## 4. ปุ่ม Action "ยืนยันตำแหน่งว่าถูกต้อง"

| ตั้งค่า | ค่า |
|---|---|
| ชื่อ | `ยืนยันตำแหน่งว่าถูกต้อง` |
| Action type | **Data: set the value of some columns in this row** (`SET_COLUMN_VALUE`) |
| Set these columns | `ยืนยันตำแหน่ง` = `TRUE` · `ผู้ยืนยันตำแหน่ง` = `=USEREMAIL()` |
| Only if this condition is true | `=AND(NOT(ISBLANK([LatLong_จากงานประจำวัน])), [ระยะจากLatLong_Actual_เมตร] > 20)` |
| Attach to column | `จุดส่งสินค้าปลายทาง` (ให้ปุ่มโผล่ติดกับช่องพิกัด) |
| Prominence | `Display_Inline` |

**ทำไมปุ่มนี้ทำงานได้** (ตามเอกสาร AppSheet): Action ที่เซ็ตคอลัมน์อื่น
**จะไม่ถูกบล็อก** จากค่าที่ผิดเงื่อนไขซึ่งมีอยู่ก่อนแล้ว — เพราะเงื่อนไขที่ผิดอยู่บนคอลัมน์อื่น
และไม่ได้ถูกแก้โดย action นี้

> ⚠️ **ข้อควรระวังสำคัญ**: ปุ่ม Action เขียนแถวทันที
> ถ้าผู้ใช้ยังไม่ได้กรอกรูป/ข้อมูลอื่นในฟอร์มแล้วกดปุ่ม → **รูปที่ยังไม่ได้บันทึกอาจหาย**
> → **แนะนำให้ผู้ใช้ติ็กช่อง `ยืนยันตำแหน่ง` ในฟอร์มเป็นหลัก** (ไม่มีข้อมูลหาย)
> และคงปุ่ม Action ไว้สำหรับกรณีแก้จากหน้า Detail/List หรือกรณีที่บันทึกข้อมูลอื่นครบแล้ว

## 5. ข้อความ "มีแก้ไข โดยคนนี้"

คอลัมน์ `ข้อความแก้ไขตำแหน่ง` (LongText, computed):
```
=IF(ISBLANK([ยืนยันตำแหน่ง]), "",
  "แก้ไขตำแหน่งจุดส่งสินค้าปลายทางโดย " & [ผู้ยืนยันตำแหน่ง]
  & " เมื่อ " & TEXT([เวลาที่ยืนยันตำแหน่ง], "DD/MM/YYYY HH:MM")
  & " (ระยะที่ยืนยัน " & TEXT([ระยะที่ยืนยัน_เมตร], "0.0") & " ม.)")
```
เพิ่มคอลัมน์ `เวลาที่ยืนยันตำแหน่ง` (DateTime) = `=IF(ISBLANK([ยืนยันตำแหน่ง]), "", NOW())`
และ `ระยะที่ยืนยัน_เมตร` (Decimal) = `=IF(ISBLANK([ยืนยันตำแหน่ง]), "", [ระยะจากLatLong_Actual_เมตร])`

**ให้เห็นเด่น**: เพิ่ม Format rule บนคอลัมน์นี้ → สีแดง/ตัวหนา เมื่อ `[ยืนยันตำแหน่ง] = TRUE`
(แอปนี้มี format rule อยู่แล้ว 11 ข้อ เช่น `อนุมัติ` → ตัวหนาสีเขียว, `รอการอนุมัติ` → สีส้ม — ใช้รูปแบบเดียวกัน)

> ถ้าอยากให้เห็นทันทีในหน้า List: ใส่ `ข้อความแก้ไขตำแหน่ง` ในคอลัมน์แรกของ slice
> หรือใช้ `Show_If`/`Label` ของคอลัมน์ `สถานะการส่ง`

## 6. ลำดับการทำ (ทำทีละขั้น ทดสอบได้ทุกขั้น)

| Phase | งาน | ผลลัพธ์ | วิธีทดสอบ |
|---|---|---|---|
| **0** | ยืนยัน `MATCH_KEY` 1 ค่า = 1 จุดส่ง? และ `LatLong_Actual` มีข้อมูลกี่ % ของแถว | ตัวเลข | เปิดชีตงานประจำวัน ดูจำนวนแถวที่ `LatLong_Actual` ไม่ว่าง + เช็ค `MATCH_KEY` ซ้ำ |
| **1** | เพิ่ม 2 คอลัมน์คำนวณ (#1, #2) — **ยังไม่บล็อกอะไร** | เห็นระยะจริงใน detail view | เปิด 3-5 แถว เทียบกับแผนที่เอาจริง |
| **2** | ทดสอบเกณฑ์ 20 ม. บนข้อมูลจริง — ดูว่ากี่ % ตกเกิน | ตัวเลข | ทำใน Google Sheet ก่อน (`=DISTANCE(...)` ไม่มีใน Sheets → ใช้ `=COS`/`Haversine` ในชีตชั่วคราว) หรือทำใน AppSheet ชั่วคราว |
| **3** | เพิ่มคอลัมน์ flag + audit (#3, #4, #5) + `Required_If` + `Valid_If` | บันทึกไม่ได้เมื่อห่างเกิน | แก้ตำแหน่งให้ห่าง 50 ม. → กด Save → ต้องโดนบล็อก |
| **4** | ทำปุ่ม Action + Format rule | กดยืนยันแล้วบันทึกได้ + เห็นข้อความ | ทดสอบทั้งแบบติ็กช่อง และแบบกดปุ่ม |

## 7. ความเสี่ยงที่ต้องระวัง

| # | ความเสี่ยง | ผลกระทบ | วิธีจัดการ |
|---|---|---|---|
| 1 | `LatLong_Actual` ว่างในหลายแถว | พนักงานบันทึกไม่ได้ทั้งระบบ | `ISBLANK(...)` → ข้ามการตรวจ (เขียนไว้แล้วในสูตร) |
| 2 | `MATCH_KEY` จับคู่ผิดแถว | ตรวจผิดจุด → พนักงานโดนบล็อกมากเกิน | **ต้องยืนยันใน Phase 0** + ทดสอบใน Phase 2 |

| 4 | เกณฑ์ 20 ม. บังคับเข้มเกิน | พนักงานทำงานไม่ได้ในที่มีสัญญาณ GPS ไม่ดี | ทดสอบใน Phase 2 ก่อนบังคับ — อาจต้อง 30-50 ม. |
| 5 | GPS เพี้ยนตอนเปิดฟอร์ม (คอนโด/ใต้ดาด) | บล็อกผิดที่ | ยกเว้นกรณีที่ผู้ใช้ยืนยันเอง (มีปุ่มแล้ว ✅) |
| 6 | เกณฑ์ 20 ม. ขัดกับเกณฑ์เดิม (40/60/100 ม. ใน `ผลการตรวจสอบงานส่ง`) | 2 มาตรฐานขัดกัน | ตัดสินใจว่า 20 ม. = **บล็อกแข็ง** (กันบันทึกผิด) ส่วน 40/60/100 ม. = **คะแนนคุณภาพ** (ไม่บล็อก) — สองอย่างคนละเรื่อง แต่ต้องอธิบายทีมให้เข้าใจ |
| 7 | ปุ่ม Action เขียนแถวทันที | รูป/ข้อมูลที่ยังไม่บันทึกหาย | ให้ผู้ใช้ติ็กช่อง flag เป็นหลัก, ปุ่ม Action เป็นทางเลือก |

## 8. ข้อความที่ควรแสดง (สรุป)

| สถานการณ์ | ข้อความ |
|---|---|
| ไม่มี `LatLong_Actual` | ไม่แสดงอะไร (ข้ามการตรวจ) |
| ห่าง ≤ 20 ม. | ไม่แสดง (ผ่าน) |
| ห่าง > 20 ม. + ยังไม่ยืนยัน | ❌ "จุดส่งสินค้าปลายทางห่างจากตำแหน่งจริง **XX.X ม.** (เกิน 20 ม.) — ถ้าตำแหน่งนี้ถูกต้อง ให้กดปุ่ม **ยืนยันตำแหน่งว่าถูกต้อง**" |
| ห่าง > 20 ม. + ยืนยันแล้ว | ⚠️ "แก้ไขตำแหน่งจุดส่งสินค้าปลายทางโดย **<อีเมล>** เมื่อ **DD/MM/YYYY HH:MM** (ระยะที่ยืนยัน XX.X ม.)" — แสดงเป็นสีแดง |
