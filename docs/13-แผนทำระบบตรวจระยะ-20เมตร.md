## 1. สิ่งที่ AppSheet ทำได้จริง (หลักฐานที่ยืนยันแล้ว)

| เรื่อง | ข้อเท็จจริง | ที่มา |
|---|---|---|
| **Initial Value คำนวณใหม่ไหม** | **คำนวณใหม่ทุกครั้งที่คอลัมน์ที่มันอ้างถึงเปลี่ยน** จนกว่าแถวจะถูกบันทึก | *"initial value expressions... will repeatedly be evaluated (as other columns are filled in) until the row is saved"* — AppSheet Community |
| **Initial Value ของแถวเก่าที่มาแก้** | **ไม่คำนวณใหม่** ต้องใช้ `Reset on edit?` บังคับ | *"you can force it to recalculate by turning on the Reset on Edit property"* |
| **`Reset on edit?` ทำงานยังไง** | เมื่อเงื่อนไขเป็นจริง **มันจะสั่งให้ Initial Value ของคอลัมน์นั้นคำนวณใหม่** | *"any column with a 'Reset on edit' expression that evaluates to TRUE will re-trigger the Initial Value expression"* |
| **`Required_If` บังคับตอนไหน** | **ทุกครั้งที่พยายามบันทึกแถว** — ทั้งจากฟอร์ม, Quick Edit, และตอนที่ App formula / initial value ถูกใส่ | เอกสารทางการ AppSheet |
| **`Required_If` บังคับได้ไหมถ้าช่องซ่อน** | **ไม่บังคับ** — *"Required? is only enforced on columns that are available to the user to change"* | AppSheet Community |
| **`Valid_If` บังคับตอนไหน** | เฉพาะ **ช่องที่มองเห็นได้** และอาจไม่เช็คถ้าผู้ใช้ไม่ได้แตะช่องนั้น | เอกสารทางการ AppSheet |
| **`DISTANCE()` คืนหน่วยอะไร** | **กิโลเมตร** → ต้องคูณ 1000 | เอกสารทางการ AppSheet |

### ✅ ข้อสรุปสำคัญที่สุด
**ตัวอย่างของคุณเองเป็นหลักฐานว่า Initial Value ใช้ได้**
สูตร `LOOKUP([ชื่องาน], "ข้อมูลชื่องานต้นทางปลายทาง", "ชื่องาน", "ระยะทางคงที่")`
ใน Initial Value ของคุณขึ้นค่าเมื่อเลือกชื่องาน → **พิสูจน์แล้วว่าแนวนี้ใช้ได้จริงในแอปคุณ**
→ แผนของ AI อีกตัวที่ "Initial Value ใช้ไม่ได้" **ผิด** และ AI อีกตัวแก้กลับมาถูกแล้ว ✓

## 3. กลไก "บันทึกไม่ได้" — 2 ชั้น (เรียงสำคัญ)

### ชั้นที่ 1 (ตัวบล็อกจริง) — `Required_If` บนคอลัมน์ `ยืนยันจุดส่ง`
```
=AND(
  ISNOTBLANK([LatLong_จากงาน]),
  [ผลตรวจระยะ_20ม] = TRUE
)
```
→ ต้องมีค่าในช่อง → พนักงาน **ต้องติ๊ก YES** ถึงจะบันทึกได้
→ เอกสารทางการยืนยันว่า `Required_If` บังคับทุกครั้งที่พยายามบันทึกแถว ✓

⚠️ **เงื่อนไขสำคัญ**: `Required?` บังคับเฉพาะช่องที่ "มองเห็นและแก้ได้"
→ ช่อง YES **ต้องมองเห็น** เวลาที่ไม่ผ่าน → ตั้ง `Show_If` = `=[ผลตรวจระยะ_20ม] = TRUE` ✓

### ชั้นที่ 2 (ข้อความสวย) — `Valid_If` บนคอลัมน์ `จุดส่งสินค้าปลายทาง`
```
=OR(
  ISBLANK([LatLong_จากงาน]),
  [ระยะจากLatLong_Actual_เมตร] <= 20,
  [ยืนยันจุดส่ง] = TRUE
)
```
**Error_Message_If_Invalid:**
```
"จุดส่งสินค้าปลายทางที่คุณกรอกห่างจากจุดจริงของงาน " & TEXT([ระยะจากLatLong_Actual_เมตร], "0.0") & " ม. (เกิน 20 ม.) — ถ้าตำแหน่งนี้ถูกต้อง ให้ติ๊ก 'ยืนยันจุดส่ง' ด้านล่าง แล้วกดบันทึกได้"
```

> ทำไมต้องมีทั้ง 2 ชั้น
> * `Required_If` = บล็อก "กดบันทึก" แน่นอน (เอกสารรับรอง) แต่ข้อความจะเป็น "Required" ของ AppSheet (ไม่บอกเหตุผล)
> * `Valid_If` = ข้อความที่อธิบายเหตุผล แต่บังคับเฉพาะช่องที่มองเห็น (และอาจไม่เช็คถ้าผู้ใช้ไม่ได้แตะช่องนั้น)
> → ใช้ด้วยกัน = ทั้งบล็อก และอธิบาย ✓

### เพิ่มความปลอดภัยอีกชั้น (แนะนำ)
`Editable_If` บน `ยืนยันจุดส่ง`:
```
=[ผลตรวจระยะ_20ม] = TRUE
```
→ ติ๊ก YES ได้เฉพาะตอนที่ "ไม่ผ่าน" เท่านั้น กันการกดล่วงหน้าเพื่อบายเลี่ยง ✓

### ล้างยืนยันเก่าเมื่อพิกัดเปลี่ยน
`Reset on edit?` บน `ยืนยันจุดส่ง`:
```
=AND(
  ISNOTBLANK([พิกัดอ้างอิงตรวจระยะ]),
  [จุดส่งสินค้าปลายทาง] <> [_THISROW_BEFORE].[จุดส่งสินค้าปลายทาง]
)
```
→ ถ้าคนขับยืนยันแล้วแต่มาลากหมุดใหม่ → ยืนยันหาย → ต้องยืนยันใหม่ ✓
(ลอกรูปแบบจาก `พิกัดตอนกดบันทึก_เปลี่ยนแล้ว` ของแอปคุณ)

## 4. ⚠️ ต้องปรับ 4 จุด (จุดที่ AI อีกตัวยังไม่ได้พูดถึง)

### 4.1 ห้ามแก้สูตรของ `พิกัดตอนกดบันทึกงาน` — ให้เพิ่มคอลัมน์ใหม่แทน

คอลัมน์นี้ถูกใช้โดย **4 คอลัมน์เดิม** ในแอปคุณ:
| คอลัมน์ที่ใช้ | ใช้ทำอะไร |
|---|---|
| `ระยะขยับจากจุดเริ่มต้น_เมตร` | **กันคนขับกดไกลร้าน** (จุดตอนเปิดฟอร์ม vs จุดตอนกดบันทึก) |
| `ผลการตรวจสอบงานส่ง` | คะแนน PASS / WARNING / FAIL (เกณฑ์ 40/60/100 ม.) |
| `เหตุผิดปกติที่ตรวจพบ` | รายการความผิดปกติ |
| `ความเร็วการเคลื่อนที่_เมตร_นาที` | ความเร็วเฉลี่ย |

**ถ้าเปลี่ยนให้จับพิกัด "ตอนเลือก Invoice" แทน "ตอนกดบันทึก"**
→ จุดทั้งสองจะเป็นตำแหน่งเดียวกัน (เปิดฟอร์ม → เลือก Invoice ห่างกันไม่กี่วินาที)
→ ระยะ ≈ 0 → **กฎเดิมที่กันคนขับกดไกลร้านจะหายไปเงียบ ๆ** ✗

→ **ทางแก้:** เพิ่มคอลัมน์ใหม่ `พิกัดตอนเลือกInvoice` แยกออกมา
แล้วใช้เป็น "จุดอ้างอิงสำรอง" แทน (คอลัมน์เดิมยังทำงานเหมือนเดิมทุกอย่าง) ✓

### 4.2 `ผู้ยืนยันจุดส่ง` ต้องเป็น Initial Value ที่อ้างคอลัมน์ยืนยัน — ห้ามใช้สูตร USEREMAIL() ธรรมดา

ถ้าเขียน `ผู้ยืนยันจุดส่ง` เป็น **App formula** = `USEREMAIL()`
→ ค่านี้คือ "อีเมลของคนที่กำลังเปิดดูแถวอยู่ตอนนี้"
→ แอดมินเปิดดูงานเก่าทีหลัง → จะเห็นอีเมลแอดมิน ✗ (ผิดต้องการ "ใครกดยืนยัน")

→ ต้องเป็น **Initial Value** ที่อ้างคอลัมน์ยืนยัน:
```
=IF(ISBLANK([ยืนยันจุดส่ง]), "", USEREMAIL())
```
→ พอคนขับติ๊ก YES → Initial Value คำนวณใหม่ตอนนั้น → ได้อีเมลคนที่กด ✓

### 4.3 ต้องมี `Reset on edit?` ด้วย ไม่ใช่แค่ Initial Value

Initial Value คำนวณใหม่เฉพาะ **ตอนสร้างแถวใหม่**
→ แถวเก่าที่คนขับกลับมาแก้ (เช่น งานที่ยังไม่ส่งเมื่อวาน) → พิกัดจะว่าง
→ ต้องมี `Reset on edit?` ที่เงื่อนไขแคบ (เฉพาะตอนเลข Invoice เปลี่ยน) ดังข้อ 2 ข้างบน ✓

### 4.4 ต้องบอกผู้ใช้ด้วยว่า "ไม่พบพิกัดจริงของงาน" — ไม่งั้นเขาจะเข้าใจผิดว่าเช็คแล้วผ่าน

กรณีที่ชีตงานประจำวัน **ไม่มี** `LatLong_Actual`
→ ระบบจะใช้ `พิกัดตอนเลือกInvoice` เป็นจุดอ้างอิงแทน
→ ถ้าคนขับเปิดฟอร์มที่ร้านแล้วเลือก Invoice ที่ร้าน → ระยะ ≈ 0 → ผ่านอัตโนมัติ
→ **กฎนี้แทบไม่กันอะไรเลยในกรณีนั้น** แต่หน้าจอจะโชว์ว่า "ผ่าน" → เข้าใจผิดว่าเช็คกับจุดจริงแล้ว

→ ต้องเพิ่มคอลัมน์สถานะบอกความจริง เช่น `สถานะจุดอ้างอิง`:
```
=IF(ISBLANK([LatLong_จากงาน]),
    "ไม่พบพิกัดจริงของงาน — ตรวจสอบได้แค่ระยะจากจุดที่เลือก Invoice",
    "ตรวจสอบกับพิกัดจริงของงาน")
```
→ แสดงเป็นสีเหลือง/สีส้มเมื่อไม่พบพิกัดจริง

## 6. ลำดับลงมือ (ทำทีละชั้น ทดสอบได้ทุกชั้น)

### ชั้นที่ 1 — คำนวณอย่างเดียว ยังไม่บล็อกอะไร
เพิ่มคอลัมน์ข้อ 1-5 (§2) + `สถานะจุดอ้างอิง` (§4.4)
เปิดฟอร์มจริงบนมือถือ 2-3 แถว แล้วดูว่า
- `พิกัดตอนเลือกInvoice` ขึ้นเมื่อเลือก Invoice หรือไม่
- `LatLong_จากงาน` มีค่าไหม
- `ระยะจากLatLong_Actual_เมตร` เป็นตัวเลขที่ดูสมเหตุสมผลไหม (เทียบกับแผนที่ขับรถ)

### ชั้นที่ 2 — กฎบล็อก
เพิ่มคอลัมน์ 6-9 + `Required_If` + `Valid_If` + `Show_If` + `Editable_If`
ทดสอบ 4 เคส (ดู §7)

### ชั้นที่ 3 — สังเกต 2-3 วัน
ดูว่ามีกี่ % ของงานที่ "ไม่ผ่าน" และกี่ % ที่คนขับกด YES
→ ถ้า "ไม่ผ่าน" เยอะเกิน ~2% → ขยับเกณฑ์เป็น 30-50 ม. แล้วทำซ้ำ
→ ถ้า "คนขับกด YES" เยอะผิดปกติ → เกณฑ์เข้มเกิน

### ชั้นที่ 4 — เปิดใช้จริงทั้งทีม
พร้อม format rule สีส้ม/แดง และข้อความแจ้งเตือน

| T4 | งานไม่มี `LatLong_Actual` | บันทึกได้ตามปกติ + ขึ้นข้อความ "ไม่พบพิกัดจริงของงาน" |

| T6 | ยืนยันแล้ว แล้วลากหมุดใหม่ | ยืนยันหาย → ต้องยืนยันใหม่ |

## 9. คำถามที่ยังต้องรู้จากข้อมูลจริง (1 ข้อ)

**เกณฑ์ 20 เมตร เหมาะไหม?**

ยังตอบไม่ได้เพราะยังไม่มีข้อมูลแถวจริง
→ ส่ง CSV 2 ตาราง (`ตารางงานประจำวัน` + `SCGนครหลวงJWDภูมิภาค`) มาให้ผม
→ ผมรัน `scripts/analyze_location_check.py` ให้ ได้ตัวเลขว่าจริงๆ ห่างเท่าไหร่ กี่ % ที่จะโดนบล็อก

ผมทดสอบกับข้อมูลจำลอง (GPS คลาด ±12 ม.) ได้ผลว่า **ที่ 20 ม. โดนบล็อก ~29%** → เกณฑ์นี้อาจเข้มเกิน
แต่ต้องดูของจริงก่อนถึงจะสรุปได้ ✓
