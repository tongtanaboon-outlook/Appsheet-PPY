## บทที่ 1 — สิ่งที่คุณมีอยู่ก่อนผมมาช่วย

คุณมี **แอป AppSheet** ที่พนักงานใช้ทำงานจริงทุกวัน ชื่อว่า **"เผ่าปัญญาทรานสปอร์ต"**
ใช้ดูแลงานขนส่งสินค้าให้ลูกค้า SCG Express / SCGJWD (เรียกสั้น ๆ ว่า "SCG")

**AppSheet คืออะไร?** — เปรียบเหมือน **Google Sheets ที่กดใช้งานได้ด้วยมือถือ**
ข้อมูลทั้งหมดอยู่ใน "ตาราง" (เหมือนชีต) แต่มีของพวกนี้เพิ่มขึ้น:
* **เครื่องคิดให้อัตโนมัติ** — เขียนสูตรครั้งเดียว ทุกครั้งที่มีข้อมูลใหม่มันคำนวณให้เอง
* **ปุ่มกด** — เช่น ปุ่ม "อนุมัติ" กดแล้วสถานะเปลี่ยนทันที
* **กฎการแสดงผล** — เช่น ถ้าอนุมัติแล้วให้ตัวหนาเป็นสีเขียว
* **บอท** — โปรแกรมที่ทำงานเองอัตโนมัติ (เช่น ดึงใบวางบิลจากระบบปริ๊นมาทุกวัน)

**คุณทำมาด้วยมือ** = สร้างตาราง สร้างคอลัมน์ เขียนสูตร ตั้งปุ่ม ทีละอย่าง
(ผมเห็นว่าคุณเรียนจาก YouTube + ถาม AI + ลองผิดลองถูก — วิธีนี้ได้ผลจริงครับ
เพราะมันคือ "เรียนรู้จากของจริง")

**ปัญหาคือ:** พอระบบโตขึ้นข้อมูลก็เยอะขึ้น และ **ไม่มีใคร (รวมทั้ง AI) รู้ว่าในแอปนี้มีอะไรอยู่บ้าง**
ยิ่งแอปใหญ่ ยิ่ง AI ตอบไม่ถูก เพราะมันเดา

## บทที่ 2 — ผมทำอะไรให้

ผม **อ่านแอปของคุณทั้งแอปออกมาเป็นแผนที่** แล้วเก็บไว้บน GitHub

> **คำถามที่คุณอาจสงสัย:** ทำไมต้องเก็บบน GitHub?
> **คำตอบ:** เพราะ AI หลายตัว (Claude, ChatGPT, Gemini, Cursor) ต่อให้เก่งแค่ไหน
> ก็ **อ่านไฟล์ในโปรเจกต์ได้** แต่ **อ่านแอป AppSheet ของคุณโดยตรงไม่ได้**
> พอเก็บเป็นไฟล์แล้ว คุณบอก AI ว่า "อ่านโฟลเดอร์นี้" → มันรู้ทุกอย่างทันที ไม่ต้องเดา

### สิ่งที่ผมดึงออกมาได้

| อย่าง | จำนวน | เปรียบเหมือน |
|---|---:|---|
| ตารางทั้งหมด | 90 | ห้องเก็บเอกสาร 90 ห้อง |
| ├ ตารางที่มีข้อมูลจริง | **29** | ห้องที่เก็บของจริง |
| ├ ตารางของบอท (เก็บชั่วคราว) | 60 | ห้องสแกนเอกสาร — เขียนแล้วลบทิ้ง |
| └ ตารางตั้งค่ารายคน | 1 | ลิ้นชักเก็บของส่วนตัว |
| คอลัมน์ (ช่อง) | 2304 | ช่องในตารางทั้งหมด |
| ช่องที่เครื่องคิดให้เอง | 319 | ช่องที่มีสูตรติดไว้ |
| ความสัมพันธ์ระหว่างตาราง | 80 | ลิงก์ "ตารางนี้เกี่ยวกับตารางโน้น" |
| ปุ่มกดทั้งหมด | 214 | ปุ่มในแอป |
| หน้าจอ (View) | 115 | หน้าจอต่าง ๆ ของแอป |
| กฎการแสดงผล | 11 | กฎ "ถ้าเป็นแบบนี้ให้แสดงแบบนั้น" |

> **สำคัญ:** ตัวเลขทุกอันนี้ **ตรงกับที่แอประบุไว้เอง 100%**
> คือผมไม่ได้เดาว่ามีกี่ตาราง แต่นับได้ครบทุกตัว ไม่มีตกหล่น
> (ถ้าตกหล่นจะมีสคริปต์จับได้ — ดูบทที่ 8)

## บทที่ 3 — ⭐ สิ่งที่สำคัญที่สุด: "ตารางจริง" กับ "ตารางบอท"

นี่คือเรื่องที่ **ทำให้ AI ตอบผิด** ได้ง่ายที่สุด ขอให้เข้าใจแบบนี้:

### ลองนึกภาพว่าคุณทำงานในห้องครัว

* **ตารางจริง (29 ตาราง)** = สมุดจดรายการของที่ขายจริง เช่น "รายการส่งของวันนี้"
  → ข้อมูลถาวร มีค่ามาแล้ว คิดเงินได้
* **ตารางบอท (60 ตาราง)** = **กระดาษชั่วคราวที่เครื่องจักรวางไว้เพื่อทำงาน แล้วลบทิ้ง**
  → เหมือนใบเสนอราคาที่พิมพ์ออกมาชั่วคราวแล้วทิ้ง เพราะฉันทำใหม่ทุกวัน

**ตัวอย่างจริงในแอปคุณ:**
* `Clear Output 7` = กระดาษผลลัพธ์ของบอท "รับเอกสาร" — พรุ่งนี้ก็เขียนใหม่
* `Process for ปริ๊นใบวางบิล Process Table` = กระดาษ "ตั้งค่าของบอทปริ๊นใบวางบิล"

### ถ้ามี AI มาวิเคราะห์ "รายได้วันนี้เท่าไหร่" โดยไม่รู้เรื่องนี้:
มันอาจไปนับแถวในตารางบอทด้วย → **ได้ตัวเลขที่โตเกินจริงหลายเท่า** แล้วรายงานว่า "รายได้วันนี้ 5 ล้าน" ทั้งที่จริงคือ 1 ล้าน

→ **นี่คือเหตุผลที่ต้องแยกให้ชัด** และผมทำไว้ให้แล้ว:
* คอลัมน์ `kind` ใน `app/tables.csv` บอกว่าตารางไหนจริง/บอท
* แยกโฟลเดอร์ `docs/tables/` (จริง) กับ `docs/process-tables/` (บอท)
* ทุกไฟล์เอกสารของตารางบอทจะมีคำเตือนหัวไฟว่า "ห้ามนับเป็นข้อมูลธุรกิจ"

## บทที่ 4 — แอปนี้ทำงานยังไง (ภาพรวม 1 วัน)

```
① ลูกค้าสั่งงานขนส่ง
        ↓
② พนักงานได้รับงาน → บันทึกลงตาราง "ตารางงานประจำวัน"
   (ที่นี่เก็บ: ใบวางบิล, ทะเบียนรถ, จุดส่งของ, ราคา, สถานะการสแกน)
        ↓
③ พนักงานขับไปส่ง → สแกนที่จุดส่ง + ถ่ายรูป
   → บันทึกลงตาราง "SCGนครหลวงJWDภูมิภาค"
   (ระบบคำนวณให้: เดินไปกี่เมตร, ใช้เวลานานไหม, เร็วแค่ไหน, ผ่านไหม/ต้องระวัง/ไม่ผ่าน)
        ↓
④ บอท "ปริ๊นใบวางบิล" ดึงใบวางบิลจากระบบปริ๊นมาทุกวัน (มี 14 เวอร์ชัน ตามคลัง/สาขา)
   → ตาราง "ข้อมูลการวางบิล"
        ↓
⑤ ระบบคิดราคา: ราคาตามระยะทาง + ค่าจุดเพิ่ม + เรทน้ำมันดีเซล
   → ตาราง "ราคาในระบบก่อนส่งสินค้า"
        ↓
⑥ เทียบราคาจริงกับราคาในระบบ → ถ้าต่างกันต้อง "เบิกส่วนต่าง"
   → ตาราง "ทำเบิกส่วนต่างScgวังน้อย" (ใหญ่ที่สุด 136 คอลัมน์)
        ↓
⑦ ผู้ดูแลกดปุ่ม "อนุมัติ" → เปลี่ยนสถานะเป็น อนุมัติ
        ↓
⑧ สรุปรายวัน/รายชิปเมนต์ → "สรุป_Shipment", "สรุป_เจ้าของสินค้า" → export เป็น Excel
        ↓
⑨ เกิดปัญหาที่หน้างาน → บอท Telegram ส่งแจ้ง → "แจ้งปัญหาระหว่างวัน"
```

**ตารางที่เป็น "หัวใจ" ของระบบ** (ถ้าจำได้แค่ 3 อัน):
1. **`ตารางงานประจำวัน`** — ข้อมูลงานทุกงาน (ทุกอย่างอ้างกลับมาที่นี่)
2. **`SCGนครหลวงJWDภูมิภาค`** — บันทึกการสแกนหน้างาน
3. **`ข้อมูลการวางบิล`** — ใบวางบิลที่ปริ๊นมาแล้ว + ราคา

## บทที่ 6 — สูตรที่ระบบคิดให้ (319 ช่อง) เข้าใจยังไง

สูตรใน AppSheet เขียนคล้าย Excel แต่มีฟังก์ชันพิเศษของ AppSheet เอง

| สูตร | แปลว่าว่า | ตัวอย่างในแอปคุณ |
|---|---|---|
| `=TODAY()` | วันนี้ | วันที่ส่งสินค้า |
| `=HERE()` | ตำแหน่ง GPS ตอนนี้ | จุดส่งสินค้าปลายทาง |
| `=USEREMAIL()` | อีเมลคนที่กำลังใช้แอป | Email พนักงาน |
| `=USERROLE()` | บทบาท (ADMIN = ผู้ดูแล) | ใช้คุมสิทธิ์แก้ไข |
| `=DISTANCE(a,b)*1000` | ระยะห่างเป็น **เมตร** | ตรวจว่าสแกนตรงจุดไหม |
| `=FILTER("ตาราง", เงื่อนไข)` | ดึงแถวที่ตรงเงื่อนไข | สรุปงานรายชิปเมนต์ |
| `=SUM(SELECT(...))` | รวมยอดแบบมีเงื่อนไข | คิดเงินเฉพาะช่วงวันที่ |
| `=IFS(เงื่อนไข1, ผล1, ...)` | เลือกคำตอบตามเงื่อนไข | ให้คะแนน PASS/WARNING/FAIL |
| `=[ชื่อRef].[ชื่อคอลัมน์]` | ดึงค่าจากตารางอื่น | ดึงชื่อลูกค้า/ชื่อปลายทาง |
| `=OR(...)`, `=AND(...)` | "หรือ" / "และ" | เงื่อนไขการแก้ไข |

> ⚠️ **`DISTANCE()` คืนหน่วย "กิโลเมตร"** แต่ชื่อคอลัมน์บอกว่า "เมตร" → ต้องคูณ 1000
> (จุดนี้ผมเจอว่าสูตรในไฟล์ PDF ถูกตัดจน "× 1000" หายไป แก้แล้วในรีโปนี้ ✅)

## บทที่ 7 — ฟีเจอร์ที่เรากำลังออกแบบ: ตรวจตำแหน่งส่งของ (เกณฑ์ 20 เมตร)

### ปัญหาที่จะแก้
พนักงานเปิดแอปไปสแกนที่จุดส่ง → ถ้าสแกนผิดที่ (เช่น GPS เพี้ยนตอนอยู่ใต้ดาด)
ระบบก็บันทึกพิกัดผิด → ข้อมูลราคา/ระยะทางผิดทั้งชุด

### ข้อมูลที่มีอยู่แล้ว
* ชีต `ตารางงานประจำวัน` มีคอลัมน์ **`LatLong_Actual`** = จุดส่งจริงที่ระบบบันทึกไว้ ✅
* ชีต `SCGนครหลวงJWDภูมิภาค` มีคอลัมน์ **`จุดส่งสินค้าปลายทาง`** = พิกัดที่พนักงานสแกน/กดบันทึก

### สิ่งที่จะทำ
1. ดึง `LatLong_Actual` มาไว้ข้าง ๆ (ผ่านลิงก์เดียวกับที่แอปใช้อยู่แล้ว = `SM_Link_SCG`)
2. คำนวณระยะห่าง → **ถ้าเกิน 20 เมตร = บันทึกไม่ได้**
3. แต่มีปุ่ม "ยืนยันตำแหน่งว่าถูกต้อง" → กดแล้วบันทึกได้
4. บันทึกไว้ด้วยว่า **ใครเป็นคนยืนยัน** (เพื่อตรวจย้อนหลัง)

### ต้องเพิ่มคอลัมน์ใหม่ 5 ตัว
| ชื่อ | ชนิด | ทำอะไร |
|---|---|---|
| `LatLong_จากงานประจำวัน` | LatLong | เก็บจุดอ้างอิงจากชีตอีกฝั่ง |
| `ระยะจากLatLong_Actual_เมตร` | Number | ระยะห่างเป็นเมตร |
| `ยืนยันตำแหน่ง` | Yes/No | ติ๊ก = "ฉันยืนยันว่าถูก" |
| `ผู้ยืนยันตำแหน่ง` | Text | เก็บอีเมลคนที่กดยืนยัน |
| `ข้อความแก้ไขตำแหน่ง` | ข้อความยาว | ข้อความ "แก้ไขโดยใคร เมื่อไร" |

### ลำดับการทำ (อย่าเพิ่งบังคับ 20 ม. ทันที!)
1. **เพิ่ม 2 คอลัมน์แรก** แค่ดูค่าก่อน (ยังไม่บล็อกอะไร)
2. **วัดด้วยข้อมูลจริง** — ส่ง CSV 2 ตารางมา ผมรันสคริปต์ให้
   (ผมทดสอบกับข้อมูลจำลองแล้ว: ถ้า GPS คลาด ±12 ม. → โดนบล็อก ~29% ที่เกณฑ์ 20 ม.
   → **ถ้าเกิน ~2% แปลว่าเกณฑ์นี้เข้มเกิน ต้องขยับเป็น 30-50 ม.**)
3. **ค่อยเพิ่มกลไกบล็อก** (ตามสูตรใน `docs/09-location-check-design.md`)
4. **ปุ่ม + กฎสีแดง**

> 💡 จุดที่ควรรู้: ถ้าคุณอยากให้ผมช่วยตัดสินเกณฑ์ ให้ส่ง CSV 2 ตาราง (`ตารางงานประจำวัน.csv` + `SCGนครหลวงJWDภูมิภาค.csv`) มาได้เลย
> วิธี export อยู่ใน `data/README.md` (เลือกทางที่ง่ายที่สุด: กด Export CSV ในตัวแอป แล้วโยนไฟล์ลง `data/`)

## บทที่ 8 — ทำไมถึง "เชื่อถือได้" (ไม่ใช่แค่เชื่อผม)

ผมไม่อยากให้คุณเชื่อคำพูดผม ผมเลยทำให้ **ตรวจเองได้**:

1. **ตัวเลขในเอกสารต้องตรงกับที่แอประบุเอง** — ถ้าผมแยกตารางตกไปสักตัว สคริปต์จะจับได้
2. **สคริปต์ `scripts/validate_repo.py` ตรวจ 24 ข้อ** ทุกครั้งที่ push (ปุ่มเขียว/แดงบน GitHub)
3. **สร้างเอกสารใหม่ได้ใน 1 วินาที** — `python3 scripts/make_docs.py`
   (ถ้าเอกสารกับข้อมูลไม่ตรงกัน สคริปต์จะแจ้ง)
4. **สคริปต์ `scripts/analyze_location_check.py` วัดจากข้อมูลจริง** ไม่เชื่อคำผม
5. **ทุกสูตรที่ผมแก้ มีที่มา** — เช่น `× 1000` ที่หายไป ผมหาเจอจาก PDF ต้นฉบับแล้วแก้และ commit ไว้

**สิ่งที่ผมยังไม่รู้ และบอกไว้ตรง ๆ** (มี 2 คอลัมน์):
`ข้อมูลการวางบิล.สถานะการอนุมัติ` กับ `ScanDocs.สรุปยอด` — สูตรซับซ้อนจน PDF ทับกัน อ่านออกมาไม่ครบ
→ ติดธงไว้ในคอลัมน์ `needs_review` ให้คุณไปเช็คในแอปครับ

## ภาคผนวก — ศัพท์ยาก ๆ ที่เจอในรีโปนี้ (แปลเป็นภาษาคน)

รายละเอียดทั้งหมดอยู่ที่ `docs/11-ศัพท์เทคนิค-แปลเป็นภาษาคน.md`

| ศัพท์ | แปลว่า |
|---|---|
| **Schema** | แบบฟอร์มว่าตารางหน้าตาหน้าตารางนี้มีคอลัมน์อะไรบ้าง |
| **Ref / คอลัมน์อ้างอิง** | ช่องที่เก็บ "รหัสของแถวในตารางอื่น" เพื่อดึงข้อมูลมาแสดง |
| **คีย์ (Key)** | ช่องรหัสประจำแถว เช่นเลขที่ใบวางบิล — ใช้ค้นแถวนั้นได้ |
| **Initial value** | ค่าเริ่มต้นที่ใส่ให้อัตโนมัติตอนสร้างแถวใหม่ |
| **Valid_If** | กฎ "ค่านี้ต้องเป็นแบบนี้ ถึงจะบันทึกได้" |
| **Required_If** | กฎ "ช่องนี้ต้องกรอก ถึงจะบันทึกได้" |
| **Editable_If** | กฎ "ใครแก้ได้" (เช่น เฉพาะ ADMIN) |
| **Show_If** | กฎ "แสดงช่องนี้ต่อเมื่อ..." |
| **Action / ปุ่มกด** | ปุ่มที่กดแล้วระบบทำอะไรให้อัตโนมัติ |
| **Bot / บอท** | โปรแกรมอัตโนมัติที่ทำงานเองตามเวลา/เงื่อนไข |
| **Process / Step Output** | กระดาษชั่วคราวของบอท (เขียนแล้วลบ) |
| **Slice** | มุมมองของตารางเดียวกันที่กรอง/เรียงข้อมูลต่างกัน |
| **Format rule** | กฎเปลี่ยนสี/ตัวหนา/ไอคอนตามเงื่อนไข |
| **View** | หน้าจอของแอป (มีหลายหน้าจอ) |
| **LatLong** | พิกัดแผนที่ (ละติจูด, ลองจิจูด) |
| **DISTANCE()** | คำนวณระยะห่างระหว่าง 2 จุด (คืนหน่วย **กิโลเมตร**) |
| **HERE()** | ตำแหน่ง GPS ของคนใช้เครื่องตอนนี้ |
| **USEREMAIL() / USERROLE()** | อีเมล / บทบาทของคนที่ล็อกอิน |
| **Security filter** | กฎซ่อนแถวจากคนที่ไม่มีสิทธิ์ |
| **Column Order List** | ลำดับการแสดงคอลัมน์ใน UI |
| **needs_review** | ธงที่ผมติ้งว่า "ค่านี้ต้องไปเช็คในแอป" |
