# ✅ เช็กลิสต์ "ฟีเจอร์นี้ทำได้ไหม?" (ใช้ก่อนแก้แอปทุกครั้ง)

> ไฟล์นี้คือ **แบบฟอร์มตรวจ** สำหรับประเมินข้อเสนอใด ๆ (จากคุณ หรือจาก AI ตัวอื่น)
> ตอบ 8 ข้อนี้ครบ = รู้แล้วว่า "ทำได้ / ต้องปรับอะไร / ทำไม่ได้"
> ผมเตรียมคำตอบของข้อ 1-6 ไว้แล้วจาก schema จริงของแอป (ดูตารางด้านล่าง)

---

## วิธีใช้ (สำหรับ AI ที่มาช่วยออกแบบ)

1. อ่านข้อเสนอจากผู้ใช้ → หา "ตารางไหน คอลัมน์ไหน" ที่เกี่ยวข้อง
2. เปิด `app/columns.csv` + `app/tables.csv` + `docs/tables/<ชื่อตาราง>.md` เพื่อตรวจ
3. ตอบ 8 ข้อทีละข้อ **พร้อมหลักฐาน** (อ้าง path + ชื่อคอลัมน์จริง)
4. สรุปเป็น 3 ประเภท: ✅ ทำได้เลย · ⚠️ ทำได้แต่ต้องปรับ X · ❌ ทำไม่ได้ เพราะ Y
5. ถ้ามีข้อที่ยังไม่รู้ → **ถาม 1 คำถามที่จำเป็นที่สุด พร้อมคำแนะนำ + ข้อดี/ข้อเสีย** (ห้ามถามเปล่า ๆ)

## ข้อ 1 — เรื่องนี้อยู่ตารางไหน คอลัมน์ไหน?

**ตรวจได้ทันที** — ทุกชื่อตาราง/คอลัมน์อยู่ใน `app/tables.csv` และ `app/columns.csv`

```bash

grep -i "คำที่ต้องการหา" app/columns.csv
```

**คำเตือน:** ชื่อที่คล้ายกันมากในแอปนี้ (ต้องดูให้รอบคอบ ไม่งั้นเลือกผิดตาราง)
| ชื่อ | อยู่ตาราง | หมายเหตุ |
|---|---|---|
| `ที่อยู่ปลายทาง` | ทั้ง 2 ชีต | ชีตงานประจำวัน = ค่าจากระบบ · ชีต SCG = ดึงมาจาก Ref |
| `จุดส่งสินค้าปลายทาง` | เฉพาะชีต SCG | LatLong, ค่าเริ่มต้น = `=HERE()` |
| `LatLong_Actual` | เฉพาะชีตงานประจำวัน | จุดส่งจริงจากฐานข้อมูล |
| `LatLong_Actual_Status` | เฉพาะชีตงานประจำวัน | สถานะการ sync |
| `ที่อยู่ปลายทาง_LatLong` | เฉพาะชีตงานประจำวัน | พิกัดจากระบบปลายทาง |
| `ที่อยู่ปลายทาง_LatLong_Api` | เฉพาะชีต SCG | ดึงจากชีตงานประจำวันด้วยชื่อปลายทาง |
| `ระยะขยับจากจุดเริ่มต้น_เมตร` | เฉพาะชีต SCG | เทียบจุดส่งกับ GPS ตอนกดบันทึก |
| `MATCH_KEY` | มีทั้ง 2 ชีต | **คนละกลไก** กับการดึงข้อมูลข้ามชีต |

## ข้อ 2 — ต้องดึงข้อมูลจากตารางไหน? มี "ทางเดิน" อยู่แล้วไหม?

**ทางเดินที่มีอยู่แล้วในแอป** (ใช้ซ้ำได้เลย ไม่ต้องสร้างกลไกใหม่)

| ทางเดิน | ชนิด | หมายเหตุ |
|---|---|---|
| `SM_Link_SCG` | Ref → `ตารางงานประจำวัน` | **ทางหลัก** ที่ชีต SCG ใช้ดึงข้อมูลทุกอย่าง |
| `ID_พนักงาน` | Ref → `ข้อมูลพนักงาน` | ผูกกับคนที่ล็อกอิน (`USEREMAIL()`) |
| `ID_Doc_Return` | Ref → `Doc_Return` | เอกสารคืนสินค้า |
| `ID_ประกาศ` | Ref → `Announcements` | ประกาศ |
| `ที่อยู่ปลายทาง_LatLong_Api` | คำนวณ | ดึงพิกัดจากชีตงานประจำวันด้วย `ชื่อปลายทาง` |
| `Related ...s` | List | ดึงแถวที่ "อ้างกลับมา" ด้วย `REF_ROWS()` |

> ⚠️ **กฎเหล็ก: ถ้าข้อมูลมาจากตารางอื่น ให้ใช้ "ทางเดิน" ที่มีอยู่แล้วเสมอ**
> เพราะ (ก) ไม่ต้องสร้างกลไกใหม่ (ข) ถ้าภายหลังเปลี่ยนวิธีจับคู่ จะแก้ที่จุดเดียว

**รูปแบบที่ใช้บ่อยในแอปนี้ (ลอกแบบได้เลย):**
```
=IF(ISBLANK([SM_Link_SCG]), "", LOOKUP([_THISROW].[SM_Link_SCG], "ตารางงานประจำวัน", "LatLong_Actual"))
```

## ข้อ 3 — มีของเดิมที่ทำหน้าที่นี้ได้อยู่แล้วไหม?

**ค่าที่ "ใกล้เคียง" อยู่แล้วในชีต SCG** — ถ้าข้อเสนอทำสิ่งที่มีอยู่แล้ว ให้ใช้ของเดิม

| คอลัมน์เดิม | ทำอะไรอยู่แล้ว |
|---|---|
| `ระยะขยับจากจุดเริ่มต้น_เมตร` | เทียบ `จุดส่งสินค้าปลายทาง` กับ `พิกัดตอนกดบันทึกงาน` (ทั้งคู่ `=HERE()`) — **คนละคู่กับที่ขอ** |
| `ผลการตรวจสอบงานส่ง` | ให้คะแนน PASS/WARNING/FAIL (เกณฑ์ 40/60/100 ม. + เวลา + ความเร็ว) |
| `เหตุผิดปกติที่ตรวจพบ` | บอกเหตุผิดปกติแบบข้อความ |
| `พิกัดตอนกดบันทึก_เปลี่ยนแล้ว` | ตรวจว่าพิกัดถูกเปลี่ยนหรือไม่ |
| `คลังสินค้า เอสซีจี เจดับเบิ้ลยูดี วังน้อย` | พิกัดคลังคงที่ (ค่าคงที่) |
| `ชื่อที่อยู่จาก_LatLong` | ชื่อที่อยู่ที่มาจากพิกัด |
| `จำนวนปลายทาง_System` / `รายชื่อปลายทาง_System` | จำนวน/รายชื่อจุดส่งของ invoice — ใช้ทำ dropdown ได้ |
| `ลำดับแรก` | บอกว่าแถวนี้เป็นจุดส่งแรกของ shipment ไหม |
| `MATCH_KEY` / `ShopKey` / `MD_ID` | คีย์ฝั่งระบบแผนที่ (คนละกลไกกับการดึงข้อมูลข้ามชีต) |

> 💡 คำถามที่ควรถามตัวเองทุกครั้ง: *"ของที่มีอยู่แล้วทำได้อยู่แล้วไหม?"*
> ถ้าตอบว่า "ทำได้" → อาจไม่ต้องเพิ่มคอลัมน์ใหม่เลย → ประหยัดเวลา + ไม่เพิ่มความซับซ้อน

## ข้อ 4 — จะ "บล็อกการบันทึก" ได้ไหม? ใช้อะไรบล็อก?

**กลไกที่ AppSheet มี (จากเอกสาร Google ยืนยันแล้ว)**

| กลไก | ผลลัพธ์ | ใช้เมื่อ |
|---|---|---|
| `Valid_If` + `Error_Message_If_Invalid` | ไม่ให้บันทึก + ขึ้นข้อความที่เรากำหนด | อยากให้พนักงานเห็นเหตุผล |
| `Required_If` | ช่องนั้น "ต้องกรอก" → กด Save ไม่ได้ | อยากบล็อกการบันทึกจริง ๆ |
| `Editable_If` | ล็อกการแก้ไข | จำกัดสิทธิ์แก้ |
| `Show_If` | ซ่อน/แสดงช่อง | ลดความรกในฟอร์ม |

**ข้อจำกัดที่ต้องรู้ (สำคัญมาก):**
1. `Valid_If` บังคับ**เฉพาะช่องที่มองเห็นได้ในฟอร์ม** → ถ้าอยากบล็อกด้วยค่าในช่องซ่อน ให้ย้ายเงื่อนไขไปตั้งที่ช่องที่**มองเห็นได้**
2. **ปุ่ม Action ที่เซ็ตคอลัมน์อื่น จะไม่ถูกบล็อก** จากค่าที่ผิดเงื่อนไขซึ่งมีอยู่ก่อนแล้ว → นี่คือกลไกที่ทำให้ "ปุ่มยืนยัน/override" ทำงานได้
3. **ปุ่ม Action เขียนแถวทันที** → ถ้ากดในฟอร์มที่ยังกรอกไม่ครบ รูป/ข้อมูลที่ยังไม่ save อาจหาย → ให้ผู้ใช้ติ๊กช่อง flag ในฟอร์มแทนปุ่ม แล้วค่อยมีปุ่มเป็นทางเลือก

**รูปแบบที่ใช้ได้ 2 ชั้น (ต้องมีทั้งคู่):**
```
ชั้นที่ 1 — Valid_If บนช่องที่ต้องการบังคับ   → ข้อความอธิบาย
ชั้นที่ 2 — Required_If บนช่อง flag                → บล็อก "กดบันทึก" จริง
```

## ข้อ 5 — ใครทำได้? (สิทธิ์)

| กลไกที่มี | ค่าในแอปนี้ | ผล |
|---|---|---|
| Security filter (ระดับแถว) | `=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())` | พนักงานเห็นเฉพาะแถวตัวเอง, ADMIN เห็นทั้งหมด |
| `Editable_If` (ระดับคอลัมน์) | เช่น `=USERROLE()="ADMIN"` | ล็อกการแก้คอลัมน์ราคา/พิกัดให้เฉพาะ ADMIN |
| `Required_If` | ตามกรณี | บังคับกรอก |

> ตารางที่มี security filter: `SCGนครหลวงJWDภูมิภาค`, `ข้อมูลการวางบิล`, `ข้อมูลการเข้าบำรุงรักษา`,
> `ตารางงานประจำวัน`, `แจ้งปัญหาระหว่างวัน`, `รับงานคืนได้เงิน200`, `ทำเบิกส่วนต่างScgวังน้อย`
